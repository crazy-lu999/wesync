# wesync共享笔记 — 夫妻共享待办小程序

夫妻两人共享一个待办清单：一方添加/勾选/删除，另一方实时可见。附甜甜的家庭相片墙、纪念日倒计时、一起完成的里程碑庆祝。

- 后端：**微信云开发**（免服务器、免域名备案）
- 配对：**6 位邀请码**（A 创建家庭 → 把码发给 B → B 输入码加入）
- 同步：写入走云函数；读取用客户端 **实时推送（watch）** 为主（对方改动即时可见），未配置时自动降级为约 3 秒轮询；自己操作后立即刷新，零延迟反馈
- 待办：完成/取消（保留划线沉底）、**重要标记**、**指派给谁（👤 头像角标）**、长按菜单编辑、**删除/清空 5 秒内可撤销**、完成撒花庆祝 + 触感反馈、神奇同步事件提示（“TA 完成了…”）
- 家庭：**相片墙**（上传/长按删除/自定义标题）、**纪念日 💗**（可多个含标题与倒计时）、改昵称、**建议墙**（公开，意见反馈升级）
- 情感化：**一起完成里程碑**（10/50/100… 达标弹窗庆祝）、**纪念日倒计时**、**每周“一起完成”小结**
- 稳定：数据**写**只经服务端——待办写入走云函数、家庭读写走云函数，只有待办的**读**用带规则的实时推送，逻辑简单、不掉安全规则坑

## 首次使用配置（5 步）

### 1. 填 AppID 和云环境 ID
- 微信开发者工具导入 `shared-todo` 目录 → 项目设置里填 **AppID**。
- 点工具左上角「云开发」→ 开通/选择环境 → 记下**环境 ID**。
- 把环境 ID 填到 `app.js` 里的 `env: 'your-env-id'`。
- 把 AppID 填到 `project.config.json` 的 `"appid"`。

### 2. 建数据库集合 + 配实时推送
云开发控制台 → 数据库 → 新建三个集合：`families`、`todos`、`feedbacks`。

> **版本更新兜底集合 `app_config`**（可选，用于极端热启动兜底）：版本更新横幅主靠 `wx.getUpdateManager().onCheckForUpdate` 自动判断（零维护）。为确保“从旧版一直挂后台、期间发版、从不重新冷启动”这类极端场景也不漏，可再建 `app_config` 集合并插入一条 `{ _id: 'latest-version', version: '当前版本号' }`，每次发版把 `version` 改成最新版号即可（前端 `onShow` 每次都对比一次）。不配则仍能覆盖常规场景，仅极端热启动的兜底会弱一些。

**`families` 集合**：保持默认权限即可（读写全走云函数）。

**`feedbacks` 集合**：保存「建议墙」的内容（用户建议 + 开发者发版动态）。保持默认权限即可，数据一律经 `submitFeedback` / `manageWall` 云函数写入。

**`todos` 集合**需要两步，让「实时同步」生效：

1. **安全规则**（进集合 → 权限设置 → 自定义安全规则）：
   ```json
   {
     "read": "auth.openid in doc.members",
     "write": "false"
   }
   ```
   - `read`：仅家庭成员可读（写云函数时已把成员 openid 列表写进 `doc.members`）。
   - `write`：禁止客户端直接写，所有写入走云函数，更安全。
2. **开通实时数据推送**：`todos` 集合 → 实时数据推送 → 开启，否则 `watch` 不生效。

> 若暂不配置上面两步，`watch` 会失败但程序**自动降级为 3 秒轮询**，功能仍可用，只是同步稍慢。

### 3. 部署云函数
在开发者工具左侧 `cloudfunctions` 目录下，**右键每个云函数文件夹** →
「上传并部署：云端安装依赖（不上传 node_modules）」。共 13 个：
`createFamily`、`joinFamily`、`getMyFamily`、`leaveFamily`、`updateNickname`、`updateAvatar`、`updateFamily`、`todoOps`、`getMyTodos`、`getLatestVersion`、`submitFeedback`、`listFeedbacks`、`manageWall`。

> ⚠️ 每次改动云函数后都要重新「上传并部署」，否则新增的 action（如相片墙/纪念日/重要/清空/里程碑）不生效。

### 4. 预览
点「预览」生成二维码，微信扫码在手机上打开。

### 5. 模拟双人测试
单人没法验证「双人同步」。两个微信号测试方法：
- 用你的微信 + 家人的微信分别扫码进入。
- 或在开发者工具里用「真机调试」+ 另一部手机分别登录不同微信号。

## 使用流程

1. **A**：打开小程序 →「创建家庭」→ 填昵称 → 得到 6 位邀请码 → 复制发给 B。
2. **B**：打开小程序 →「我有邀请码，加入」→ 输入码 + 昵称 → 进入共享清单。
3. 任一方添加/完成/编辑/删除待办，对方列表**实时推送即时刷新**（未开通推送则约 3 秒内）出现；自己操作立即本地刷新，零延迟。
4. **完成待办**：点前面的圆圈 → 划线沉底 + 撒花 + 轻震，并计入「已完成」；再点一次可取消。**重要事项**：长按待办选「设为重要」加星标，会排在最前。
5. **编辑/删除**：**长按**待办 → 菜单选「编辑」改内容，或「删除」——删除/清空有 **5 秒撤销**窗口，点「撤销」可恢复。顶部「清空已完成」可批量清理。
6. **相片墙**：「我的」页上传照片（上限 9 张）、长按删除、自定义标题。照片全部展示在网格里，两人都能传、都能看。
7. **一起完成里程碑**：累计完成达 10/50/100… 时弹窗庆祝。
8. **改昵称**：进「我的」页 → 家庭成员里点自己 → 输入新昵称 → 保存，对方看到的昵称与待办署名同步更新。
9. **建议墙与版本**：首页右上角 →「建议墙」→ 写下想法（全平台公开）；被采纳的会标上「已上线」。页底与「使用说明」页显示当前**版本号**（发版前同步改 `utils/config.js` 的 `APP_VERSION`）。每位用户提交建议后，都能到建议墙看到自己的建议状态与开发者回复——感受到这个小程序还在持续更新、一听建议就改。
10. **版本更新提醒**：发版后用户打开小程序会自动收到两个升级入口（**双保险，热启动也能看到**）——①冷启动弹窗“有更新啦 🎉”一键重启（`app.js` `checkUpdate()` 的 `onUpdateReady`），由微信自动判断，无需手动维护；②首页顶部常驻“我藏了个新功能，快重启去拆礼物吧 ❤️”横幅：`onShow` 时先读 `onCheckForUpdate` 写入的全局 `hasUpdate`，再无条件查一次 `app_config` 版本号对比本地 `APP_VERSION` 兜底（覆盖“从不重新冷启动”的极端热启动），点横幅弹窗“有更新啦 🎁 / 去拆礼物”重启升级。
11. **换机/重装**：家庭、待办、相片墙都与你的微信号绑定，换手机或重装后登录同一微信号即可自动找回，无需重新输邀请码。

## 技术要点

- **实时同步**：首页用客户端 `watch` 实时订阅本家庭 todos，对方任意改动**即时**刷新；`onShow`/`onHide` 启停订阅。`watch` 不可用时自动降级为 3 秒轮询。
- **语义化同步提示**：渲染前把新快照与上一份快照做 diff，把对方（非本人）的改动（添加/完成/恢复/重要/编辑）转成“TA 完成了…”提示条；自己发起的动作在短窗口内被「静默」，不自说自话。
- **完成过渡动画**：完成时整卡轻微缩放并沉到半透明 + 删除线从左到右划出 + 勾选弹出（CSS `@keyframes`），并延迟到动画播完再沉底，避免生硬瞬移；另加 `wx.vibrateShort` 轻震反馈。
- **删除/清空可撤销**：删除与清空采用「先本地隐藏 + 5 秒撤销窗口 + 超时才真实删」策略，点撤销直接恢复、云端零删除，避免先删再回滚的复杂补偿。
- **重要标记排序**：待办长按「设为重要」→ `todoOps` 的 `important` action 写库，未完成中「重要优先」再按创建时间倒序（`renderTodos`/`sortTodos` 规则一致）。
- **完成人与里程碑**：`todoOps` 的 `toggle` 在完成时记录 `doneBy/doneNick`（服务端由 openid 取昵称），并累加家庭文档 `families.totalDone`；前端达到 `config.DONE_MILESTONES` 中的值时弹窗庆祝（每档只在本地庆祝一次）。
- **相片墙**：上传走 `wx.cloud.uploadFile` 到存储 → `updateFamily` 的 `addPhotos` 把 fileID 写入家庭 `photos`（上限 9，超出自动删最旧）→ 标题/删除均由 `updateFamily` 服务端写。首页网格用 `gridPhotos`（全部照片）渲染，长按直接删除照片。
- **首屏秒显**：待办列表缓存到本地，再进页面先渲染缓存再做服务端覆盖；退出家庭同步清缓存。
- **openid 信任 / 读写分离 / members 一致性 / 邀请码唯一性 / 昵称可改 / 乐观更新**：见下文原样保留（均已实现于云函数）。

> 更多细节：待办写入、家庭读写全走云函数（服务端），`todos` 只读走带 `auth.openid in doc.members` 规则的实时推送，不依赖脆弱的客户端写规则，逻辑简单、不易掉安全坑。
