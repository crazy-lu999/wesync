# 我们的小本本 — 夫妻共享待办小程序

夫妻两人共享一个待办清单：一方添加/勾选/删除，另一方实时可见。

- 后端：**微信云开发**（免服务器、免域名备案）
- 配对：**6 位邀请码**（A 创建家庭 → 把码发给 B → B 输入码加入）
- 同步：写入走云函数；读取用客户端 **实时推送（watch）** 为主（对方改动即时可见），未配置时自动降级为约 3 秒轮询；自己操作后立即刷新，零延迟反馈
- 提醒：待办可设「时间提醒」，到点通过微信**订阅消息**推送通知（一次性订阅，无需本地后台）
- 稳定：数据**写**只经服务端——待办写入走云函数、家庭读写走云函数，只有待办的**读**用带规则的实时推送，逻辑简单、不掉安全规则坑

## 目录结构

```
shared-todo/
├── app.js / app.json / app.wxss      # 入口、配置、全局样式
├── project.config.json               # appid + 云环境配置
├── utils/
│   ├── db.js                         # 云函数封装 + todos 增删改查 + 提醒 + 轮询拉取
│   ├── config.js                     # 运行配置（订阅消息模板 ID）
│   └── format.js                     # 时间格式化
├── pages/
│   ├── index/                        # 列表页/引导页合一，实时推送为主、轮询兜底，待办增/删/改/设提醒
│   ├── create/                       # 创建家庭，生成邀请码
│   ├── join/                         # 凭邀请码加入
│   └── me/                           # 家庭信息、成员、我的提醒、退出
└── cloudfunctions/
    ├── createFamily/                 # 建家庭 + 生成唯一邀请码
    ├── joinFamily/                   # 凭码加入（满员/码错校验，同步旧待办 members）
    ├── getMyFamily/                  # 查当前用户家庭
    ├── leaveFamily/                  # 退出（最后一人离开则清理数据，移除旧待办 members）
    ├── updateNickname/               # 修改自己在本家庭中的昵称
    ├── todoOps/                      # 待办增删改（服务端写，带成员列表）；新增待办可写提醒
    ├── getMyTodos/                   # 待办读取（服务端读 + 降级轮询）
    ├── getMyReminders/               # 查询当前用户未触发的提醒
    ├── cancelReminder/               # 取消一条提醒，并清空对应待办提醒字段
    └── reminderTrigger/              # 定时触发器：扫描到期提醒，下发订阅消息（每分钟）
```

## 首次使用配置（5 步）

### 1. 填 AppID 和云环境 ID
- 微信开发者工具导入 `shared-todo` 目录 → 项目设置里填 **AppID**。
- 点工具左上角「云开发」→ 开通/选择环境 → 记下**环境 ID**。
- 把环境 ID 填到 `app.js` 里的 `env: 'your-env-id'`。
- 把 AppID 填到 `project.config.json` 的 `"appid"`。

### 2. 建数据库集合 + 配实时推送
云开发控制台 → 数据库 → 新建三个集合：`families`、`todos`、`reminders`。

**`families` 集合**：保持默认权限即可（读写全走云函数）。

**`reminders` 集合**：保持默认权限即可（读写全走云函数 / 定时触发器）。

**`todos` 集合**需要两步，让「实时同步」生效：

1. **安全规则**（进集合 → 权限设置 → 自定义安全规则）：
   ```json
   {
     "read": "auth.openid in doc.members",
     "write": "false"
   }
   ```
   - `read`：仅家庭成员可读（写云函数时已把成员 openid 列表写进 `doc.members`）。
   - `write`：禁止客户端直接写，所有写入走云函数，更安全。
2. **开通实时数据推送**：`todos` 集合 → 实时数据推送 → 开启，否则 `watch` 不生效。

> 若暂不配置上面两步，`watch` 会失败但程序**自动降级为 3 秒轮询**，功能仍可用，只是同步稍慢。

### 2.5 配置订阅消息（仅提醒功能需要）
提醒通过微信「订阅消息」推送，首次使用前需开通：

1. 小程序主体需已完成**微信认证**（未认证则公众平台无「订阅消息」入口）。
2. 登录 [mp.weixin.qq.com](https://mp.weixin.qq.com) → **功能 → 订阅消息** → 公共模板库 → 选用含「温馨提醒 / 日期」字段的模板（如「待办提醒」）。
3. 复制**模板 ID**，填到两处（须保持一致）：
   - `utils/config.js` 的 `REMIND_TMPL_ID`
   - `cloudfunctions/reminderTrigger/index.js` 顶部的 `TMPL_ID`
4. `reminderTrigger/index.js` 的 `MINI_PROGRAM_STATE`：**真机测试**期间改为 `'develop'`，**正式发布**前改回 `'formal'`。

> 局限：订阅消息是**一次性**的，用户每授权一次才能收到一条。本作策略是「添加带提醒的待办时弹一次授权」，授权用尽(43101)的提醒会自动跳过不再轰炸。

### 3. 部署云函数
在开发者工具左侧 `cloudfunctions` 目录下，**右键每个云函数文件夹** →
「上传并部署：云端安装依赖（不上传 node_modules）」。共 10 个：
`createFamily`、`joinFamily`、`getMyFamily`、`leaveFamily`、`updateNickname`、`todoOps`、`getMyTodos`、`getMyReminders`、`cancelReminder`、`reminderTrigger`。

> `reminderTrigger` 首次部署时务必勾选**「同时上传云函数触发器」**（`config.json` 里配了每分钟 timer）。否则定时扫描不会启动。

### 4. 预览
点「预览」生成二维码，微信扫码在手机上打开。

### 5. 模拟双人测试
单人没法验证「双人同步」。两个微信号测试方法：
- 用你的微信 + 家人的微信分别扫码进入。
- 或在开发者工具里用「真机调试」+ 另一部手机分别登录不同微信号。

## 使用流程

1. **A**：打开小程序 →「创建家庭」→ 填昵称 → 得到 6 位邀请码 → 复制发给 B。
2. **B**：打开小程序 →「我有邀请码，加入」→ 输入码 + 昵称 → 进入共享清单。
3. 任一方添加/勾选/删除待办，对方列表**实时推送即时刷新**（未开通推送则约 3 秒内）出现。
4. 想改自己的昵称：进「我的」页 → 轻点「我的昵称」卡片 → 输入新昵称 →「保存」，对方看到的昵称同步更新；之后新建的待办也会带上新昵称。
5. 修改待办内容：**长按**待办 → 底部菜单选「编辑」→ 输入框进入编辑态改内容 →「保存」。
6. 设置提醒：点输入框前的 **🔔 开关** → 选日期/时间 → 点「添加」并确认订阅授权。到点微信「服务通知」会收到提醒，点它跳回待办页。
7. 查看/取消提醒：进「我的」页 → 「我的提醒」卡片列出自建的所有未触发提醒（含触发时间与倒计时），点「取消」即可。

## 技术要点

- **实时同步**：首页用客户端 `watch` 实时订阅本家庭 todos，对方任意改动（增/勾/删）**即时**刷新；`onShow`/`onHide` 启停订阅，不常驻耗资源。若 `watch` 不可用（未开通推送/未配读规则）自动降级为 3 秒轮询，永不中断。
- **操作零延迟**：自己 add/编辑/删除成功后立即 `fetchTodos()` 刷新，自己操作**立即可见**，不依赖网络回调时机。
- **编辑能力**：`todoOps` 新增 `edit` action，服务端改写 `content`；长按待办弹底部菜单选「编辑」，复用底部输入框进入编辑态（原文回填 + 自动聚焦 + 保存/取消）。
- **提醒闭环**：添加带 `remindAt` 的待办时，`todoOps` 同时写 `reminders` 集合并存 `openid`；`reminderTrigger`（每分钟 timer）扫描到期项，调用 `cloud.openapi.subscribeMessage.send` 下发订阅消息，成功即标记 `triggered`，授权用尽(43101)则标记跳过防轰炸；删除/取消会同步清理提醒。提醒只发给创建者本人。
- **首屏秒显**：待办列表缓存到本地 `wx.setStorageSync`，再次进入页面时先用缓存立即渲染，再后台拉服务端覆盖；且首次拉到数据前不显示「还没有待办」的空态（避免冷启动时的假空白）。退出家庭时同步清缓存。
- **openid 信任**：创建/加入/查询/退出/待办写全走云函数，openid 来自 `wx.getWXContext()`，客户端无法伪造。
- **读写分离**：待办**写**（`todoOps`）和家庭读写全走云函数（服务端），客户端只对 `todos` 做受规则约束的**读**（`auth.openid in doc.members`），不依赖脆弱的客户端写规则。
- **members 一致性**：`joinFamily`/`leaveFamily` 会同步新旧成员的 `todos.members`，避免新成员读不到旧待办、或已退出者仍能读到。
- **邀请码唯一性**：生成后查 `count()`，重复则重生成，最多重试 20 次。
- **昵称可改**：昵称存于家庭文档 `memberNicks[openid]`，`updateNickname` 云函数按当前 openid 点号路径单独更新，只改自己不动他人；昵称会用于新建待办的创建者标注。
- **乐观更新**：勾选先改本地 UI 再写库，失败回滚，体验流畅。
