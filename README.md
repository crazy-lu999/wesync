# wesync共享笔记 — 夫妻共享待办小程序

夫妻两人共享一个待办清单：一方添加/勾选/删除，另一方实时可见。附甜甜的家庭相片墙、纪念日倒计时、一起完成的里程碑庆祝。

- 后端：**微信云开发**（免服务器、免域名备案）
- 配对：**6 位邀请码**（A 创建家庭 → 把码发给 B → B 输入码加入）
- 同步：写入走云函数；读取用客户端 **实时推送（watch）** 为主（对方改动即时可见），未配置时自动降级为约 10 秒轮询（拉失败退避，并有限次尝试重回实时）；自己操作后本地即时更新，零延迟反馈
- 待办：完成/取消（保留划线沉底）、**重要标记**、长按菜单编辑、**删除/清空 5 秒内可撤销**、完成撒花庆祝 + 触感反馈、神奇同步事件提示（“TA 完成了…”）
- 家庭：**相片墙**（上传/长按删除/自定义标题）、**纪念日 💗**（可多个含标题与倒计时）、改昵称、**意见反馈**（告诉我们你的想法，安静送达开发者）
- 情感化：**一起完成里程碑**（10/50/100… 达标弹窗庆祝）、**纪念日倒计时**、**每周“一起完成”小结**
- 稳定：数据**写**只经服务端——待办写入走云函数、家庭读写走云函数，只有待办的**读**用带规则的实时推送，逻辑简单、不掉安全规则坑

## 首次使用配置（5 步）

### 1. 填 AppID 和云环境 ID
- 微信开发者工具导入 `shared-todo` 目录 → 项目设置里填 **AppID**。
- 点工具左上角「云开发」→ 开通/选择环境 → 记下**环境 ID**。
- 把环境 ID 填到 `app.js` 里的 `env: 'your-env-id'`。
- 把 AppID 填到 `project.config.json` 的 `"appid"`。

### 2. 建数据库集合 + 配实时推送
云开发控制台 → 数据库 → 新建三个集合：`families`、`todos`、`feedbacks`。

> **版本更新兜底集合 `app_config`**（可选，用于极端热启动兜底与「更新内容」展示）：版本更新横幅主靠 `wx.getUpdateManager().onCheckForUpdate` 自动判断（零维护）。为确保“从旧版一直挂后台、期间发版、从不重新冷启动”这类极端场景也不漏，可再建 `app_config` 集合并插入一条 `{ _id: 'latest-version', version: '当前版本号', title: '这次更新', notes: ['第一条更新说明', '第二条'], releasedAt: '2025-01-01' }`。每次发版改 `version` / `title` / `notes` / `releasedAt` 即可（前端 `onShow` 会对比一次）。不配也能用：更新弹窗和更新日志会走 `utils/release-notes.js` 的本地兜底，只是旧版横幅点开时没有云端更新内容预览。

**`families` 集合**：保持默认权限即可（读写全走云函数）。

**`feedbacks` 集合**：保存用户提交的**私密意见反馈**（仅开发者可见）。数据一律经 `submitFeedback` 云函数写入，开发者可在云开发控制台查看。原「建议墙」的公开列表、点赞、公开回复、公开发布动态等社交能力已全部下线。

> 建议在集合 → 权限设置 → 自定义安全规则中直接关闭客户端读写，确保反馈不会被任何客户端读取：
> ```json
> { "read": false, "write": false }
> ```>
> 历史数据清理：若此前已上线过公开建议墙，建议在控制台删除 `feedbacks` 中 `type` 为 `suggestion` / `update` 的旧公开数据，只保留私有反馈（`type: 'feedback'`）。

#### 反馈管理（仅开发者本人）
1. 确认 `utils/config.js` 的 `ADMIN_OPENID` 与 `cloudfunctions/adminFeedback/index.js` 的 `ADMIN_OPENID` 一致（填你自己的 openid）。
2. 部署 `adminFeedback` 云函数。
3. 用开发者微信打开小程序 →「我的」页会出现「反馈管理」入口，可查看全部反馈、标记已读、删除。
4. 普通用户看不到该入口；即使手动打开页面，云函数也会按 openid 拒绝，读不到任何数据。
5. 不想进小程序时，也可以直接在云开发控制台 → 数据库 → `feedbacks` 查看原始记录。

**`todos` 集合**需要两步，让「实时同步」生效：

1. **安全规则**（进集合 → 权限设置 → 自定义安全规则）：
   ```json
   {
     "read": "auth.openid in doc.members",
     "write": false
   }
   ```
   - `read`：仅家庭成员可读（写云函数时已把成员 openid 列表写进 `doc.members`）。
   - `write`：禁止客户端直接写，所有写入走云函数，更安全。（注意是布尔 `false`，**不要加引号**，加分号会报 `rule invalid`）
2. **开通实时数据推送**：`todos` 集合 → 实时数据推送 → 开启，否则 `watch` 不生效。

> 若暂不配置上面两步，`watch` 会失败但程序**自动降级为约 10 秒轮询**，功能仍可用，只是同步稍慢、也费云函数额度。
>
> ⚠️ **踩坑提醒**：`watch` 的读权限校验是**整查询级**的——只要查询结果里有一条文档当前用户读不了，整个 `watch` 就建立失败（SDK 判定为不可重试），日志里表现为 `[watch] todos error` + `[sync] watch 不可用，降级为轮询`。常见原因：早期创建的老待办没有 `members` 字段，或 `members` 还是加入前的旧快照。修法是先跑一次 `cloudfunctions/fixTodoMembers`（传 `{}` 试运行看报告，传 `{"apply":true}` 真正写库），把每条待办的 `members` 对齐成所属家庭的当前成员，再把权限改回上面的自定义规则。别用「所有用户可读写」——那等于全库待办裸奔，而且任何人都能直接改删。

### 3. 部署云函数
在开发者工具左侧 `cloudfunctions` 目录下，**右键每个云函数文件夹** →
「上传并部署：云端安装依赖（不上传 node_modules）」。共 12 个：
`createFamily`、`joinFamily`、`getMyFamily`、`leaveFamily`、`updateNickname`、`updateFamily`、`todoOps`、`getMyTodos`、`getLatestVersion`、`submitFeedback`、`adminFeedback`、`sendReminders`。

> 另附一次性数据修复工具 `cloudfunctions/fixTodoMembers`（不参与业务，需要时部署 + 云端测试手动跑）。

> ⚠️ 审核合规改造后，`listFeedbacks`、`toggleWallLike`、`manageWall` 已删除，无需再部署；如云端仍有旧版，请在云开发控制台一并删除。

> ⚠️ 每次改动云函数后都要重新「上传并部署」，否则新增的 action（如相片墙/纪念日/重要/清空/里程碑）不生效。

#### 待办提醒（订阅消息）额外 3 步

「选了提醒时间但收不到通知」几乎都是下面几道关之一没过：

1. **部署 `sendReminders` 并确认定时触发器生效**：云开发控制台 → 云函数 → `sendReminders` → 触发器，应能看到 `todoReminder`（每分钟）。没有就重新「上传并部署」（`config.json` 会被一起上传）。
2. **配置云函数凭证**（HTTP 直连通道必需）：云开发控制台 → 云函数 → `sendReminders` → 配置 → 环境变量。两种写法任选：
   - **写法 A（两个变量）**：`WX_APPID` = 小程序 AppID；`WX_SECRET` = 小程序 AppSecret
   - **写法 B（一个变量，适合控制台只能加一条的情况）**：`WX_CRED` = `appid,secret`（逗号分隔；也支持 JSON `{"appid":"..","secret":".."}`）
   AppSecret 在后台「开发管理 → 开发设置」生成；**不要写进代码或仓库**。
3. **模板 ID 两处一致**：`utils/config.js` 的 `REMIND_TMPL_ID` 与 `cloudfunctions/sendReminders/index.js` 的 `REMIND_TMPL_ID` 必须相同，且模板已在「小程序后台 → 订阅消息」审核通过。
4. **字段名对得上模板**：`sendReminders` 里的 `REMIND_FIELDS`（默认 `thing1` / `time3`）必须与模板里的字段码一致，否则报 47003。`diagnose` 会把模板真实字段列出来。
5. **小程序版本状态**：`sendReminders` 的 `MINIPROGRAM_STATE`，**预览/体验阶段填 `developer` 或 `trial`**，正式发布后改回 `formal`。填错会导致发送失败。

> 发送采用**双通道自动降级**：先试云调用（`cloud.openapi`），若报 `-501001 INVALID_WX_ACCESS_TOKEN`（平台拿不到凭证）则自动改用「自换 access_token + HTTP 直连」，后者只依赖环境变量里的 AppID/AppSecret。
>
> **发布正式版前必做**：把云函数环境变量 `MINI_STATE` 设为 `formal`（否则消息会跳到开发版打不开）；体验版则设 `trial`。不设环境变量时默认 `developer`。
>
> 诊断：入参 `{ "action": "diagnose" }` 会分别检测两条通道，并列出模板真实字段码（对照 `REMIND_FIELDS`）。
>
> 自测：入参 `{ "action": "test", "openid": "你的openid", "content": "测试提醒" }`，会立即发一条并返回用了哪条通道、详细错误码（43101 无额度 / 47003 参数不合法 / 40003 openid 错 / 40125 AppSecret 不对 / 40164 IP 不在白名单）。
>
> 注意：订阅消息是**一次性**的，用户每授权一次只能收到一条，用完需再次授权（保存带提醒的待办时会自动弹授权框）。

## 使用流程

1. **A**：打开小程序 →「创建家庭」→ 填昵称 → 得到 6 位邀请码 → 复制发给 B。
2. **B**：打开小程序 →「我有邀请码，加入」→ 输入码 + 昵称 → 进入共享清单。
3. 任一方添加/完成/编辑/删除待办，对方列表**实时推送即时刷新**（未开通推送则约 10 秒内）出现；自己操作立即本地更新，零延迟。
4. **完成待办**：点前面的圆圈 → 划线沉底 + 撒花 + 轻震，并计入「已完成」；再点一次可取消。**重要事项**：长按待办选「设为重要」加星标，会排在最前。
5. **编辑/删除**：**长按**待办 → 菜单选「编辑」改内容，或「删除」——删除/清空有 **5 秒撤销**窗口，点「撤销」可恢复。顶部「清空已完成」可批量清理。
6. **相片墙**：「我的」页上传照片（上限 9 张）、长按删除、自定义标题。照片全部展示在网格里，两人都能传、都能看。
7. **一起完成里程碑**：累计完成达 10/50/100… 时弹窗庆祝。
8. **改昵称**：进「我的」页 → 家庭成员里点自己 → 输入新昵称 → 保存，对方看到的昵称与待办署名同步更新。
9. **意见反馈与版本**：进「我的」页 →「意见反馈」→ 有想法、想要的功能都可以告诉我们，每一条都会认真看。开发者本人登录后，「我的」页会额外出现「反馈管理」入口，可查看全部反馈、标记已读或删除（入口与服务端都校验 openid，普通用户不可见也读不到）。页底与「使用说明」页显示当前**版本号**（发版前同步改 `utils/config.js` 的 `APP_VERSION`）。
10. **版本更新提醒**：发版后用户打开小程序会自动收到两个升级入口（**双保险，热启动也能看到**）——①冷启动弹窗“有更新啦 🎉”一键重启（`app.js` `checkUpdate()` 的 `onUpdateReady`），由微信自动判断，无需手动维护；②首页顶部常驻“我藏了个新功能，快重启去拆礼物吧 ❤️”横幅：`onShow` 时先读 `onCheckForUpdate` 写入的全局 `hasUpdate`，再无条件查一次 `app_config` 版本号对比本地 `APP_VERSION` 兜底（覆盖“从不重新冷启动”的极端热启动），点横幅先展示“这次更新了什么”，再引导重启升级。
11. **更新说明与更新日志**：升级到新版本后首次进入首页，会弹一次「这次更新」说明（每个版本只弹一次，首次安装不打扰）；「我的 → 更新日志」可随时回看最近几个版本。发版时同步更新 `utils/release-notes.js` 与云端 `app_config` 的 `notes`。
12. **换机/重装**：家庭、待办、相片墙都与你的微信号绑定，换手机或重装后登录同一微信号即可自动找回，无需重新输邀请码。

## 发版流程（建议）

1. 改 `utils/config.js` 的 `APP_VERSION`。
2. 在 `utils/release-notes.js` 数组最前面加本次版本的 `version / title / notes`（1~3 条，写用户能看懂的话）。
3. 云开发控制台 → 数据库 → `app_config` → `latest-version`，同步改 `version` / `title` / `notes` / `releasedAt`。
4. 有云函数改动就重新部署（1.0.16 无业务云函数改动，可跳过）。
5. 上传并提交审核（上传时版本号填 `1.0.16`，与 `APP_VERSION` 一致）。

> 更新说明里不要写“公开 / 社区 / 社交 / 点赞 / 关注”等词；写“待办可以设提醒了”这种用户能直接感知的变化。

## 发版记录

**v1.0.16**（当前）
- **同步更稳（治“卡”的根）**：`watch` 建立失败不再“一降级永不回头”—— 按 30s / 2min / 10min 三次机会自动尝试重回实时，成功即停轮询、状态恢复绿点；兜底轮询 3s → 10s，拉失败指数退避到 60s，并改成「上次拉完再排下次」+ 并发互斥，不再堆积请求；`syncStart` 幂等（冷启动不再订阅两遍）；定时器/关闭函数移出 `data`，不再进 AppData。
- **写操作零等待**：新增用云函数返回的 id 本地插入，勾选/重要/编辑成功后就地补字段，不再“写完再拉一次全量”；顺手修掉勾选/设重要**失败回滚不生效**的老问题（`slice()` 共享条目引用）。
- **删除不再闪回**：新增隐藏名单（`_hidden`），撤销窗口 5s + 真实删除 + 快照确认全程不渲染，不再“撤销条 → 又冒出来一次 → 才消失”；删除失败改为「如数还回 + 提示」，另有 30s 超时兜底。
- **完成后不再跳回**：新增乐观保护（`_optimistic`），勾选后 5s 内以本地状态为准（连完成人/完成时间一起兜住），服务端快照跟上即解除保护。
- **相片墙不再闪**：临时 URL 改为「优先复用页面上已显示的」，缓存里也存显示用 URL（冷启动同样命中图片缓存），只有 URL 真过期、图片加载失败（`binderror`）时才用新 URL 就地替换。
- **「我的」页配色回春**：家庭成员头像改为「我 = 珊瑚橙 / TA = 葆粉」渐变 + 白描边 + 高光；纪念日卡改柔和渐变 + 左侧彩条 + 4 档色系轮换，日期行改为「日期 + 彩色天数胶囊」（当天为渐变实心胶囊）。
- **可维护性**：`watch` 报错现在会打印 `errCode / errMsg`（以前只有一个 minified 的 `T`）；新增一次性数据修复工具 `cloudfunctions/fixTodoMembers`（本次线上巡检结果：68 条 `alreadyOk`，无需修数据）；README 补充 watch 整查询级权限踩坑、轮询策略与 `syncStart` 幂等说明。
- **本次无业务云函数改动**，无需重新部署；仅前端 + 配置变更。

## 技术要点

- **实时同步**：首页用客户端 `watch` 实时订阅本家庭 todos，对方任意改动**即时**刷新；`onShow`/`onHide` 启停订阅，`syncStart` 幂等（同一家庭不会重复订阅）。`watch` 不可用时自动降级为 10 秒轮询（拉失败指数退避到 60 秒，并按 30s/2min/10min 三次机会重回实时）。
- **写操作零等待**：新增/勾选/重要/编辑成功后直接改本地列表（新增用云函数返回的 id 本地插入），不再「写完再拉一次全量」。
- **语义化同步提示**：渲染前把新快照与上一份快照做 diff，把对方（非本人）的改动（添加/完成/恢复/重要/编辑）转成“TA 完成了…”提示条；自己发起的动作在短窗口内被「静默」，不自说自话。
- **完成过渡动画**：完成时整卡轻微缩放并沉到半透明 + 删除线从左到右划出 + 勾选弹出（CSS `@keyframes`），并延迟到动画播完再沉底，避免生硬瞬移；另加 `wx.vibrateShort` 轻震反馈。
- **删除/清空可撤销**：删除与清空采用「先本地隐藏 + 5 秒撤销窗口 + 超时才真实删」策略，点撤销直接恢复、云端零删除，避免先删再回滚的复杂补偿。
- **重要标记排序**：待办长按「设为重要」→ `todoOps` 的 `important` action 写库，未完成中「重要优先」再按创建时间倒序（`renderTodos`/`sortTodos` 规则一致）。
- **完成人与里程碑**：`todoOps` 的 `toggle` 在完成时记录 `doneBy/doneNick`（服务端由 openid 取昵称）；累计数 `families.totalDone` 只在**该待办首次完成**时 `+1`（待办上打 `countedDone` 标记），取消后重新勾选不会重复计数。前端达到 `config.DONE_MILESTONES` 中的值时弹窗庆祝（每档只在本地庆祝一次）。
- **相片墙**：上传走 `wx.cloud.uploadFile` 到存储 → `updateFamily` 的 `addPhotos` 把 fileID 写入家庭 `photos`（上限 9，超出自动删最旧）→ 标题/删除均由 `updateFamily` 服务端写。首页网格用 `gridPhotos`（全部照片）渲染，长按直接删除照片。
- **首屏秒显**：待办列表缓存到本地，再进页面先渲染缓存再做服务端覆盖；退出家庭同步清缓存。
- **openid 信任 / 读写分离 / members 一致性 / 邀请码唯一性 / 昵称可改 / 乐观更新**：见下文原样保留（均已实现于云函数）。

> 更多细节：待办写入、家庭读写全走云函数（服务端），`todos` 只读走带 `auth.openid in doc.members` 规则的实时推送，不依赖脆弱的客户端写规则，逻辑简单、不易掉安全坑。
